# Prototype the CQ Read Broker and prove export safety

Type: prototype
Status: resolved
Assigned: dev
Parent: [Design and launch reusable Restricted Group Policy](../map.md)
Blocked by: 02

## Question

What is the narrowest credential-owning ALPS/MOLY broker that exposes only approved read capabilities without giving the agent `WitsSession`, `WitsHTTP`, arbitrary query objects, write facades, credentials, or owner filesystem access? Build a disposable executable prototype around explicit fields, notes, dependency, history, attachment-list, and download-to-task-root operations; separately force CQ export against harmless ALPS and MOLY fixtures to determine whether it is mutation-free and bounded. Decide session refresh ownership, identifier/query validation, attachment handling, response limits without business truncation, and the evidence required to prove zero CQ mutation by independent readback.

- 2026-08-17 — Resolution: Use a host-side, credential-owning CQ Read Broker/RPC. The agent-facing CQ surface is exactly `get_fields`, `list_notes`, `get_dependency`, `get_history`, `list_attachments`, `download_attachment`, and `export_crs`; it never receives `WitsSession`, `WitsHTTP`, credentials, raw WQL/SQL/`queryDefine`, saved-query identifiers or mutation, record/note/attachment write facades, arbitrary URLs, or owner filesystem paths.
  - The broker owns login/logout/refresh. The prototype opens a fresh authenticated session for each backend read; production may pool or refresh only behind the broker and may retry only idempotent reads.
  - CR identifiers, result/filter fields, operators, and values are typed and broker-validated. Their allowlists are policy-versioned; there is no raw-query escape hatch and no separate zero-predicate “dump everything” operation in this decision.
  - Small complete responses may return inline; larger complete responses become task-root artifacts. There is no successful truncated response or business row/size cap. Live probing established that legacy `startRow` is a page number and a smaller `limit` may be ignored, so the broker advances `1,2,...` until explicit `hasNext=false`; repeated pages, an empty nonterminal page, malformed rows, or backend failure return `INCOMPLETE_RESULT` and remove `.partial` rather than silently truncate.
  - Attachment listing returns metadata plus a random one-use token bound to task, CQ system, and CR. Download accepts only that token, sanitizes the server filename, and writes beneath broker-resolved `task-root/downloads/`; the caller supplies no path.
  - “CQ export” is an approved typed CQ read streamed to an atomic `.jsonl`/`.csv` task-root artifact. It does not save/delete a CQ query or call `getQueryFileByJson`; only the local ephemeral artifact is written. Normal origin-egress and brokered-confidential checks still apply before Teams delivery.
  - Fresh independent audit re-ran the live ALPS/MOLY proof at `2026-08-17T07:53:56Z`: all seven operations succeeded on both systems, both exact-fixture exports were complete and untruncated, all fourteen before/after CQ-state surfaces matched, no forbidden backend method appeared, and exercised source hashes matched. Boundary/UI evidence also matched current sources. A focused temporary ad-hoc verification (explicitly not a suite-green claim) separately re-proved `startRow=1,2`, two-row completion, repeated-page and page-two-failure fail-closed cleanup, pre-backend path rejection, missing raw/mutation methods, and all evidence/source hash bindings; its temporary script and earlier exploratory scripts were removed.
  - The prototype does not claim cross-page snapshot consistency when CQ data changes during a large export. That newly sharp question is tracked by [Define CQ export consistency across changing pages](16-define-cq-export-consistency-across-changing-pages.md), which is now unblocked.
